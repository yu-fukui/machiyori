# まちより 発注

小売店の発注システム。商品を選ぶと取引先ごとに発注書（A4・PDF）を作り、メール・インターネットFAX で送るか、印刷して FAX 機（複合機の PC-FAX）で送る。

- 店舗は複数（実店舗・外販）。外販は1回ごとに店舗として登録する（名称・会場の場所＝住所・期間）。期間が終わった外販は発注の画面に出ない
- 納品のしかたは「外販の会場に納品」「店舗に納品」「集荷」「指定の住所」。実店舗の発注は自分の店舗への納品か集荷、外販は全部から選べる（はじめは会場に納品、納品希望日は期間の始め）。指定の住所は「納品先」画面にいくつでも登録でき、日時は発注のときに入れる
- 商品には仕入れ価格（税抜）と販売価格（税込）を登録する。発注書には仕入れ価格が載る
- 商品の一覧は、店舗ごとの発注の多い順に並ぶ（昇順・降順、品番順・品名順も選べる）。☆ でお気に入りに登録できる（スタッフごと）
- 発注書ごとに備考を書ける。発注履歴には発注した人が出る
- 発注書のボタン（PDFを保存・印刷・メール・FAX）を押すたびに、PDF を Google ドライブの指定フォルダにも保存する
- スタッフは複数。アカウントは管理者が「スタッフ」画面で ID とパスワードを決めて作る（自分での登録はない）。パスワードを忘れた人は、管理者が「パスワードを決め直す」で新しいパスワードにする。商品・取引先・店舗・設定を直せるのは管理者だけ
- ID は半角英数字かメールアドレス。メールアドレスはそのまま、半角英数字の ID は「ID@machiyori.invalid」というメールアドレスとして Supabase Auth に持つ（どちらもメールは送らない）。ログイン画面では ID（またはメールアドレス）だけを入れればよい。前からのメールアドレスのアカウントは、メールアドレスでそのままログインできる
- 商品・取引先は画面で登録するか、CSV で読み込む（Excel の Shift_JIS の CSV も読める）
- 発注書は現場の様式（発注書 FAX 用.xlsx）に合わせた並び：発注日（令和）・発注元は会社（「設定」の会社名・住所・電話・ご担当者）・合計金額・希望納期・支払条件・販売場所（店舗）・納品先・品番・品名／数量／単位／単価／金額（10行）・備考と小計／消費税／合計金額。ご担当者は店舗に担当者があればそちらを載せる
- 発注番号は `PO-店舗コード-日付-連番`（例 `PO-A-20261027-001`）。金額・消費税（8%・10% を分けて計算）はデータベース側で計算する
- 作った発注書は、送る（メール・FAX・印刷・PDFを保存）か下書き保存すると履歴に残る。店や取引先の情報をあとで直しても、作った発注書は変わらない
- 商品の品番は「品番（Airレジ）」＝ Airレジに登録した商品ID。ほかにバーコードと発注ライン（最低在庫数。いまは一律 10）を登録できる。発注画面で Airレジの在庫 CSV を読み込むと、発注ラインを下回った商品に「発注ライン − 在庫数」の発注数が入る（CSV の「商品ID」などを、まず品番（Airレジ）と、なければバーコード（頭の # を除く）と結びつけ、「現在在庫数・在庫数」などを在庫として読む。Airレジの CSV の1行目「v200」は飛ばす）
- 発注画面のいちばん上に、在庫データの日時を大きく出す（Airレジの CSV のファイル名にある書き出し日時。なければ読み込んだ日時）。7日以上前か、まだ読み込んでいないときは赤で知らせ、発注書を作る前に「古い在庫のまま発注書を作る」にチェックしてもらう
- 読み込んだ在庫は店舗ごとにデータベースに保存する（stock_levels・stock_imports）。どのパソコンからでも同じ在庫が見える。読み込むたびに、その店舗の在庫をまるごと置き換える（週に1回の読み込みを想定）
- 発注画面の並びに「在庫の足りない順」がある。読み込んだ在庫 CSV の在庫数と発注ラインから、足りない数（発注ライン − 在庫数）の多い順に並ぶ（在庫か発注ラインがない商品はいちばん後ろ）。在庫 CSV を読み込むと、この並びになる
- 発注書が何枚もあるときは、FAX の発注書をまとめて印刷し、送れたらまとめて送信済みにできる。メールの取引先にはまとめて送れる
- 「月の一覧」で、取引先ごとにその月の発注の合計を出し、届いた請求書の金額との差額とチェック済みを記録できる（CSV 書き出し・印刷つき）
- 取引先には区分（買取・委託）を登録できる

## しくみ

| 部分 | 使うもの |
|---|---|
| 画面 | Vite + React（`src/`）。Vercel に置く |
| データ・ログイン | Supabase（Postgres・Auth・Storage）。表と権限は `supabase/migrations/` |
| 発注書 PDF | ブラウザで A4 の発注書を画像にして PDF にする（`src/lib/pdf.ts`） |
| 送信 | Supabase Edge Function `send-order` が Gmail（SMTP・アプリ パスワード）でメールを送る。FAX は「メールtoFAX」のサービスの宛先へ PDF 付きメールを送る |
| ドライブ保存 | Edge Function `save-to-drive` が、代表の Google アカウントで動く Apps Script（`google-apps-script/drive-save.gs`）に PDF を渡す |

画面は `anon` の権限では何も読めない。ログインした、権限が「スタッフ」か「管理者」の人だけが読める（RLS）。

## 立ち上げ

### 1. Supabase

1. Supabase で新しいプロジェクトを作る（リージョンは Tokyo）
2. `supabase/migrations/` のファイルを番号順に流す（`supabase db push`、または SQL Editor に貼る）
3. Authentication → Sign In / Providers → Email を有効にする
4. **最初のアカウントが管理者になる**。Authentication → Users → Add user で代表のアカウントを作る（Auto Confirm にする）。2人目からは、代表が画面の「スタッフ」で ID とパスワードを決めて作る
5. 関数を置く：`supabase functions deploy admin-users`（アカウントを作る・パスワードを決め直す。関数の中で管理者か確かめる。秘密の値は要らない）
6. 自分での登録を止める：Authentication → Sign In / Providers → 「Allow new users to sign up」を OFF にする（画面に登録ボタンはないが、念のため）

### 2. メール送信（Gmail）

1. 送信に使う Gmail を決める（発注専用のアカウントを作るのがおすすめ）
2. その Gmail で 2 段階認証を ON にし、Google アカウントの「アプリ パスワード」を作る（16 文字）
3. Supabase の Edge Functions → Secrets に入れる（秘密の値はリポジトリやチャットに書かない）
   - `GMAIL_USER`：送信に使う Gmail のアドレス
   - `GMAIL_APP_PASSWORD`：アプリ パスワード
   - `MAIL_FROM_NAME`：送信者の名前（なくてもよい。空なら店名）
4. 関数を置く：`supabase functions deploy send-order`（`supabase/config.toml` で `verify_jwt = false`。関数の中でログインと権限を確かめる）

送ったメールは、その Gmail の「送信済み」に残る。取引先の返信と FAX サービスの送信結果も、その Gmail に届く（返信先を変えたいときは「設定」の返信先）。個人の Gmail は 1 日に送れる数に上限がある（約 500 通）。

### 3. 画面（Vercel）

1. Vercel でこのリポジトリを読み込む（Framework: Vite）
2. 環境変数に `VITE_SUPABASE_URL` と `VITE_SUPABASE_ANON_KEY`（Supabase の Project URL と anon / publishable key）を入れる
3. Supabase の Authentication → URL Configuration の Site URL に Vercel の URL を入れる

手元で動かすとき：`.env.example` を `.env.local` にコピーして値を入れ、`npm install` → `npm run dev`。

### 4. 最初のデータ

管理者でログインして、次の順に入れる。

1. 店舗（店舗コード・店名・種類・住所など。移動型店舗は「納品先」も）
2. 取引先（CSV なら「取引先」画面の「ひな形」で列を確かめる）
3. 商品（CSV の「取引先コード」で取引先と結びつく）
4. 設定（インターネットFAX の宛先の形・消費税の端数）

## FAX の送り方

### ① インターネットFAX（メールtoFAX）

1. メールtoFAX のあるサービスを契約する
2. サービスに **送信元のメールアドレス（`GMAIL_USER`）を登録**する。登録していないアドレスからのメールは FAX にならないサービスが多い
3. 「設定」画面に、サービスが決めている宛先の形を入れる。`{fax}` のところに取引先の FAX 番号（数字だけ）が入る（例 `{fax}@サービスのドメイン`）
4. 件名・本文の決まり（暗証番号を件名に入れる、本文を送り状にする、など）がサービスにあれば、`supabase/functions/send-order/index.ts` の FAX の件名・本文を合わせる

送信の結果（届いた・届かなかった）は、サービスから送信元のアドレスにメールで届く。システムの「送信済み」は「サービスが受け付けた」という意味。

### ② 複合機の PC-FAX・FAX 機（インターネットFAX を設定するまで）

「設定」の FAX の宛先が空のあいだは、発注書の「FAXで送る（印刷）」を押すと、上に FAX 送信先・送信元・送信枚数の欄を付けた **FAX 用の発注書を印刷**する。

1. 印刷画面のプリンターで、複合機の FAX ドライバー（PC-FAX）を選ぶ。または FAX 機用に紙に印刷する
2. 宛先に取引先の FAX 番号を入れて送る
3. 印刷画面を閉じると「送れましたか？」と出るので、「送れた」を押す（送信済み・印刷・FAX機 として記録される）

## Google ドライブへの保存

発注書のボタン（PDFを保存・印刷・メールで送る・FAXで送る）を押すたびに、発注書の PDF を指定のフォルダに保存する。発注月ごとのフォルダ（例 `2026-10`）に分け、同じ発注書は新しいものに置き換える。

1. 保存先のフォルダを Google ドライブで作る（Apps Script を動かすアカウントが編集できるフォルダ）
2. https://script.google.com で新しいプロジェクトを作り、`google-apps-script/drive-save.gs` の中身を貼る
3. ファイルの上のほうの `SECRET` を、自分で決めた長い合言葉（英数字 20 文字以上）に変えて保存する
4. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」。次のユーザーとして実行：**自分**、アクセスできるユーザー：**全員**。初回は Google ドライブへのアクセスを許可する
5. 出てきたウェブアプリの URL と合言葉を、Supabase の Edge Functions → Secrets に入れる：`DRIVE_WEBHOOK_URL`・`DRIVE_WEBHOOK_SECRET`
6. 発注システムの「設定」に、保存先フォルダの URL を貼って保存する
7. 関数を置く：`supabase functions deploy save-to-drive`

フォルダが空のあいだは保存しない。保存に失敗しても、印刷や送信はそのまま進む（画面に理由が出る）。

## CSV の列

- 取引先：`取引先コード, 取引先名, 区分, 宛名, メール, FAX, 電話, 送り方, メモ, 使う`（区分は「買取」「委託」「買取・委託」か空、送り方は「FAX」か「メール」）
- 商品：`取引先コード, 取引先名, 品番（Airレジ）, 品名, 規格, 単位, 仕入れ価格, 販売価格, 税率, バーコード, 発注ライン, 使う`（仕入れ価格は税抜、販売価格は税込で空でもよい、税率は 8 か 10、品番（Airレジ）は Airレジの商品ID（前のひな形の「品番」の列も読む）、発注ラインは空でもよい（空なら在庫 CSV で発注数が入らない）、使うは 1 か 0。前のひな形の「単価」は仕入れ価格として、バーコードは頭の # を除いて読む、「最低在庫数」は発注ラインとして読む。バーコード・発注ラインの列がない CSV では、登録ずみの値を変えない）

同じコード（取引先コード、または 取引先＋品番）の行は上書きする。「登録ずみのコードは上書きしない」を選ぶと、新しいコードの分だけ追加する。CSV にない商品・取引先は消えない。品番が空の行は毎回新しく追加する。

## 開発

```sh
npm install
npm run dev        # 手元で動かす
npm run build      # 型チェックと本番ビルド
```

- 新しい表を作るマイグレーションには、必要な GRANT を同じファイルに書く（Supabase は新しい表に Data API の権限を自動で付けない）。`anon` には何も与えない
- 金額の計算はデータベースの `create_orders` で行う。画面から送った金額は使わない
